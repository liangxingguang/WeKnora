# WeKnora 核心模块详细说明

## 1. Agent 引擎

### 1.1 概述

Agent 引擎是 WeKnora 的智能推理核心，实现了 ReAct（Reasoning + Acting）框架，能够自主编排知识检索、MCP 工具与网络搜索来完成复杂多步任务。

### 1.2 核心组件

#### 1.2.1 AgentEngine

**文件**: [internal/agent/engine.go](file:///d:/workplace/Weknora/internal/agent/engine.go)

`AgentEngine` 是 Agent 执行的核心引擎，负责：
- 管理对话上下文和状态
- 执行 ReAct 循环（Think → Act → Observe）
- 处理工具调用和结果
- 管理上下文窗口和 Token 预算

**关键方法**:

```go
// Execute 执行 Agent
func (e *AgentEngine) Execute(
    ctx context.Context,
    sessionID, messageID, query string,
    llmContext []chat.Message,
    imageURLs ...[]string,
) (*types.AgentState, error)
```

#### 1.2.2 Think 阶段

**文件**: [internal/agent/think.go](file:///d:/workplace/Weknora/internal/agent/think.go)

思考阶段调用 LLM 进行推理，分析当前状态并决定下一步行动。

**核心逻辑**:
1. 构建包含对话历史和工具定义的消息
2. 调用 LLM 获取响应（包含思考和工具调用）
3. 解析响应中的工具调用指令

#### 1.2.3 Act 阶段

**文件**: [internal/agent/act.go](file:///d:/workplace/Weknora/internal/agent/act.go)

行动阶段执行 LLM 选择的工具调用。

**核心逻辑**:
1. 从工具注册表查找工具
2. 验证工具参数
3. 执行工具并获取结果
4. 处理工具执行错误

#### 1.2.4 Observe 阶段

**文件**: [internal/agent/observe.go](file:///d:/workplace/Weknora/internal/agent/observe.go)

观察阶段处理工具执行结果，并更新 Agent 状态。

**核心逻辑**:
1. 将工具结果添加到对话历史
2. 更新 AgentState
3. 准备下一轮循环

#### 1.2.5 Finalize 阶段

**文件**: [internal/agent/finalize.go](file:///d:/workplace/Weknora/internal/agent/finalize.go)

总结阶段生成最终回答。

**核心逻辑**:
1. 检查是否达到终止条件
2. 调用 LLM 生成最终回答
3. 清理资源

### 1.3 ReAct 循环

```
┌─────────────────────────────────────────────────────────────┐
│                     ReAct 循环                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Round 1:                                                  │
│   ┌───────┐    ┌───────┐    ┌──────────┐    ┌──────────┐   │
│   │ Think │───▶│ Act   │───▶│ Observe  │───▶│ Update   │   │
│   │ (LLM) │    │(Tools)│    │(Results)│    │(Context) │   │
│   └───────┘    └───────┘    └──────────┘    └──────────┘   │
│         │                                                    │
│         ▼                                                    │
│   Round 2: (重复直到完成或达到最大迭代次数)                    │
│   ┌───────┐    ┌───────┐    ┌──────────┐    ┌──────────┐   │
│   │ Think │───▶│ Act   │───▶│ Observe  │───▶│ Update   │   │
│   └───────┘    └───────┘    └──────────┘    └──────────┘   │
│         │                                                    │
│         ▼                                                    │
│   ┌──────────┐                                              │
│   │ Finalize │ (生成最终回答)                                 │
│   └──────────┘                                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.4 上下文窗口管理

Agent 引擎实现了智能上下文窗口管理：

1. **Token 估算**: 使用 BPE 算法估算消息 Token 数
2. **上下文压缩**: 当上下文超过最大 Token 数时，压缩历史消息
3. **记忆整合**: 使用 LLM 对历史对话进行摘要

**相关文件**:
- [internal/agent/token/estimator.go](file:///d:/workplace/Weknora/internal/agent/token/estimator.go)
- [internal/agent/memory/consolidator.go](file:///d:/workplace/Weknora/internal/agent/memory/consolidator.go)

## 4. RAG 检索流水线

### 4.1 概述

RAG（Retrieval-Augmented Generation）流水线负责从知识库中检索相关内容。

### 4.2 检索流程

```
用户查询 → Query Rewrite → 多路检索 → 结果合并 → Rerank → 返回
```

### 4.3 核心组件

#### 4.3.1 查询重写

**文件**: [internal/application/service/chat_pipeline/](file:///d:/workplace/Weknora/internal/application/service/chat_pipeline)

使用 LLM 对用户查询进行重写和扩展，提高检索准确性。

#### 4.3.2 多路检索

支持多种检索策略并行执行：

| 策略 | 说明 |
|------|------|
| **Dense Retrieval** | 向量相似度检索 |
| **Sparse Retrieval (BM25)** | 关键词检索 |
| **GraphRAG** | 知识图谱检索 |
| **Parent-Child Chunking** | 父子分块检索 |

#### 4.3.3 结果合并

**文件**: [internal/application/service/chat_pipeline/merge.go](file:///d:/workplace/Weknora/internal/application/service/chat_pipeline/merge.go)

使用 RRF（Reciprocal Rank Fusion）算法合并多路检索结果。

#### 4.3.4 重排序

**文件**: [internal/application/service/chat_pipeline/rerank.go](file:///d:/workplace/Weknora/internal/application/service/chat_pipeline/rerank.go)

使用专门的 rerank 模型对检索结果进行重排序。

### 4.4 检索器注册

**文件**: [internal/application/service/retriever/](file:///d:/workplace/Weknora/internal/application/service/retriever)

支持多种向量数据库作为检索后端：

| 向量数据库 | 驱动文件 |
|------------|----------|
| PostgreSQL (pgvector) | 内置 |
| Elasticsearch | `internal/application/repository/retriever/` |
| OpenSearch | `internal/application/repository/retriever/` |
| Milvus | `internal/application/repository/retriever/milvus/` |
| Weaviate | 内置 |
| Qdrant | 内置 |
| Apache Doris | `internal/application/repository/retriever/doris/` |
| 腾讯云 VectorDB | 内置 |

## 6. 分块策略

### 6.1 概述

分块策略决定如何将文档分割为适合检索的小块。

### 6.2 分块器架构

**目录**: [internal/infrastructure/chunker/](file:///d:/workplace/Weknora/internal/infrastructure/chunker)

### 6.3 三层分块策略

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| **Heading Splitter** | Markdown 文档 | 基于标题结构分割 |
| **Heuristic Splitter** | 结构化文档 | 基于章节标记、视觉分隔符 |
| **Recursive Splitter** | 通用文本 | 基于字符数递归分割 |

### 6.4 自适应选择

系统会先对文档进行分析，然后选择最合适的分块策略：

1. 分析文档结构特征
2. 评估各策略适用性
3. 选择最优策略
4. 执行分块

### 6.5 分块参数

```yaml
chunk_size: 512          # 分块大小（字符数）
chunk_overlap: 80        # 分块重叠（字符数）
split_markers:           # 分割标记
  - "\n\n"
  - "\n"
  - "。"
```
