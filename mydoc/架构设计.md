# WeKnora 架构设计

## 整体架构

WeKnora 采用全流程模块化解耦架构，从文档解析、向量化、检索到大模型推理，每个组件均可灵活替换与扩展。

**Agent 配置结构** (`types/agent.go`):

```go
type AgentConfig struct {
    MaxIterations       int        // 最大 ReAct 迭代次数
    AllowedTools        []string   // 允许的工具列表
    Temperature         float64    // LLM 温度
    KnowledgeBases      []string   // 可访问的知识库 ID
    SystemPrompt        string     // 统一系统提示词
    WebSearchEnabled    bool       // 是否启用网络搜索
    MultiTurnEnabled    bool       // 是否启用多轮对话
    MCPSelectionMode    string     // MCP 选择模式
    SkillsEnabled       bool       // 是否启用技能
    ParallelToolCalls   bool       // 是否并行执行工具调用
    MaxContextTokens    int        // 最大上下文 Token 数
    LLMCallTimeout      int        // LLM 调用超时时间
}
```

## 数据流

### 文档处理流程

```
用户上传文件 → Handler.knowledge.Create → Service.knowledge.Process
    → 文档解析(docreader) → 分块(chunker) → 向量化(embedder)
    → 向量存储(vectorstore) → 知识记录写入(Repository)
```

### RAG 问答流程

```
用户提问 → Handler.session.QA → Service.session_knowledge_qa.Execute
    → ChatPipeline.Search(检索) → ChatPipeline.Rerank(重排序)
    → ChatPipeline.Merge(结果合并) → LLM 生成 → 返回结果
```

### Agent 执行流程

```
用户提问 → Handler.session.AgentQA → Service.session_agent_qa.Execute
    → AgentEngine.Execute → Think(思考) → Act(执行工具)
    → Observe(观察结果) → Finalize(总结) → 返回结果
```

## 安全架构

### 认证授权

- JWT Token 认证
- API Key 认证
- OIDC 集成
- RBAC 角色权限控制

### 数据安全

- AES-256-GCM 静态加密（API Key、MCP 凭据）
- gRPC TLS + Token（app ↔ docreader）
- 防 SSRF HTTP 客户端
- 技能沙箱隔离

### 权限模型

四级角色矩阵：

| 角色 | 权限 |
|------|------|
| Owner | 完全控制，可删除租户 |
| Admin | 管理租户配置、成员 |
| Contributor | 管理自己创建的资源 |
| Viewer | 只读访问 |

## 可观测性

### Langfuse 集成

- ReAct 循环追踪
- Token 消耗统计
- 工具调用追踪
- 检索流水线追踪
- 文档解析时间线

### 日志系统

- structured logging (logrus)
- 支持 JSON 格式输出
