# WeKnora 开发指南

## 环境准备

### 系统要求

| 项目 | 版本要求 |
|------|----------|
| Go | 1.26.0+ |
| Node.js | 20.x+ |
| pnpm | 8.x+ |
| Docker | 20.10+ |
| Docker Compose | 2.0+ |

### 安装依赖

#### 后端依赖

```bash
cd WeKnora
go mod download
```

#### 前端依赖

```bash
cd frontend
pnpm install
```

## 快速开发模式

### 启动基础设施

```bash
make dev-start
```

这会启动 PostgreSQL、Redis 和 docreader 服务。

### 启动后端

```bash
make dev-app
```

后端服务会在 http://localhost:8080 运行。

### 启动前端

```bash
make dev-frontend
```

前端服务会在 http://localhost:5173 运行。

### 开发优势

- ✅ 前端修改自动热重载
- ✅ 后端修改快速重启（5-10秒）
- ✅ 无需重新构建 Docker 镜像
- ✅ 支持 IDE 断点调试

## 新增功能开发

### 新增 API 接口

#### 步骤

1. 在 `internal/types/` 中定义数据类型
2. 在 `internal/application/repository/` 中实现数据访问
3. 在 `internal/application/service/` 中实现业务逻辑
4. 在 `internal/handler/` 中实现 HTTP 处理
5. 在 `internal/router/` 中注册路由

#### 示例

**1. 定义类型**

```go
// internal/types/custom.go
type CustomResource struct {
    ID        string    `json:"id"`
    Name      string    `json:"name"`
    CreatedAt time.Time `json:"created_at"`
}
```

**2. 实现 Repository**

```go
// internal/application/repository/custom.go
type CustomResourceRepository interface {
    Create(ctx context.Context, resource *types.CustomResource) error
    GetByID(ctx context.Context, id string) (*types.CustomResource, error)
    List(ctx context.Context, page, pageSize int) ([]*types.CustomResource, error)
    Update(ctx context.Context, resource *types.CustomResource) error
    Delete(ctx context.Context, id string) error
}
```

**3. 实现 Service**

```go
// internal/application/service/custom.go
type CustomResourceService struct {
    repo CustomResourceRepository
}

func (s *CustomResourceService) Create(ctx context.Context, name string) (*types.CustomResource, error) {
    resource := &types.CustomResource{
        ID:        uuid.New().String(),
        Name:      name,
        CreatedAt: time.Now(),
    }
    err := s.repo.Create(ctx, resource)
    return resource, err
}
```

**4. 实现 Handler**

```go
// internal/handler/custom.go
type CustomHandler struct {
    service *service.CustomResourceService
}

func (h *CustomHandler) Create(c *gin.Context) {
    var req struct {
        Name string `json:"name"`
    }
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }
    resource, err := h.service.Create(c.Request.Context(), req.Name)
    if err != nil {
        c.JSON(500, gin.H{"error": err.Error()})
        return
    }
    c.JSON(200, resource)
}
```

**5. 注册路由**

```go
// internal/router/router.go
func SetupRouter() *gin.Engine {
    r := gin.Default()
    customHandler := &handler.CustomHandler{
        service: service.NewCustomResourceService(repo),
    }
    r.POST("/api/v1/custom-resources", customHandler.Create)
    return r
}
```

### 新增 Agent 工具

#### 步骤

1. 在 `internal/agent/tools/` 中创建工具文件
2. 实现 `Tool` 接口
3. 在 `internal/agent/tools/registry.go` 中注册工具

#### 示例

```go
// internal/agent/tools/custom_tool.go
package tools

import (
    "context"
    "encoding/json"
    
    "github.com/Tencent/WeKnora/internal/types"
)

type CustomTool struct{}

func (t *CustomTool) Name() string {
    return "custom_tool"
}

func (t *CustomTool) Description() string {
    return "执行自定义操作"
}

func (t *CustomTool) Parameters() json.RawMessage {
    params := map[string]interface{}{
        "type": "object",
        "properties": map[string]interface{}{
            "input": map[string]interface{}{
                "type":        "string",
                "description": "输入参数",
            },
        },
        "required": []string{"input"},
    }
    data, _ := json.Marshal(params)
    return data
}

func (t *CustomTool) Execute(ctx context.Context, args json.RawMessage) (*types.ToolResult, error) {
    var params struct {
        Input string `json:"input"`
    }
    if err := json.Unmarshal(args, &params); err != nil {
        return nil, err
    }
    result := &types.ToolResult{
        Success: true,
        Output:  "处理结果: " + params.Input,
    }
    return result, nil
}
```

## 常见问题

### 1. 端口冲突

```bash
# 查找占用端口的进程
netstat -tlnp | grep 8080

# 杀死进程
kill -9 <pid>
```

### 2. 数据库连接失败

检查 `.env` 文件中的数据库配置：

```bash
DB_USER=weknora
DB_PASSWORD=your-password
DB_NAME=weknora
DB_HOST=postgres
DB_PORT=5432
```

### 3. 前端无法连接后端

检查前端配置：

```bash
# frontend/public/config.js
window.WEKNORA_CONFIG = {
    API_BASE_URL: 'http://localhost:8080/api/v1'
};
```

### 4. 文档解析失败

检查 docreader 服务状态：

```bash
docker compose logs docreader
```

### 5. LLM 调用失败

检查模型配置和网络连接：

```bash
# 在 Web UI 中测试模型连接
# Settings → Models → Test Connection
```
